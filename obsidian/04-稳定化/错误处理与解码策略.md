## 第一部分: 错误处理(论文 §III-C2)

### 动机

LLM 在工具调用中容易**传播错误**、停止探索(弱模型尤甚)。
论文借鉴 Reflexion 的反馈思想,用**预定义规则**标记明显错误的行为,
向 controller 注入"错误消息 + 建议",降低无意义动作频率——
**不终止循环**,模型收到反馈后自行调整。

### 三类错误

| 类型 | 触发条件 | 反馈示例(节选) |
| --- | --- | --- |
| (i) 重复调用 | 无状态工具以相同参数被再次调用 | "tool 'log_agent' was already invoked with identical arguments at step 2..." |
| (ii) Trivial 输入 | 传给专家工具的参数过短(< 5 字符) | "input to expert tool 'log_agent' is trivial..." |
| (iii) 过早 finalize | 未调用过任何信息收集工具就 finalize | "finalize called before thorough investigation..." |

### 实现(ErrorDetector)

```python
class ErrorDetector:
    calls: list[CallRecord]        # 工具调用历史(工具名 + 参数 hash + 步号)
    info_tool_calls: set[str]      # 已成功调用的信息收集工具

    record_call(tool, kwargs, step)      # 每步执行前记录
    record_info_tool(tool)               # 信息收集工具成功返回快照时记录
    detect(tool, kwargs, step) -> str|None  # 返回错误反馈文本或 None
```

要点:
- **参数 hash**:`md5(json.dumps(kwargs, sort_keys))`,相同参数(含快照键)
  视为重复——expert 工具不豁免(相同输入的重复分析同样无意义,
  这是真实运行中发现并修正的决策);
- **enabled 开关**:`variant="react"` 时关闭(基线对照);
- 反馈文本走 `System: Error: ...` 通道注入,计入 Invalid Rate 分子。

### 真实运行证据

demo_es_conn_timeout 真实轨迹(13 步):模型曾 3 次用相同快照键重复调用
log_agent,全部被拦截并注入反馈;模型收到反馈后**停止重试、换策略、
最终成功 finalize**——这正是论文设计的行为。

## 第二部分: 解码策略(论文 §IV-A)

### 默认 greedy

论文用 greedy 保证可复现性(评估与消融的前提)。API 模式下映射为
`temperature=0`。

### 自适应重复惩罚

```
生成 token 数 > 4096(疑似循环)?
  → 重启生成, +0.5 frequency_penalty +0.5 presence_penalty
  → 仍超限可再次叠加(默认最多 3 轮)
```

抑制"重复退化"(repetitive degeneration,论文引 Holtzman et al.);
OpenAI 兼容协议用 presence/frequency 近似 vLLM 的 repetition penalty
(PRD 记录的降级策略)。

### SC 采样配置

`sampling` 模式: temperature 0.9, top_p 0.6(对齐 Vicuna 默认,论文原值),
仅供 TSC 采样使用。

### 为什么"默认采样"会崩(论文实测)

纯采样解码 + 无历史示范 → 模型乱调工具:Pass Rate 99% → 70%,
Invalid Rate 7.9% → 44.8%。这是 [[TSC与文本聚合]] 选择"greedy 主轨迹 +
中途采样"的根本原因。
